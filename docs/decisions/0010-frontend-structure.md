# 0010 — Frontend structure, auth adapters and "Soon" navigation

**Status:** accepted · Phase 1

- **Auth adapters.** One `AuthAdapter` interface with `DevAuthAdapter` (AUTH_MODE=dev, token in
  localStorage) and `EntraAuthAdapter` (MSAL redirect flow against
  `https://<subdomain>.ciamlogin.com/`, session storage). The rest of the app never branches on the
  mode. In Entra mode the tree is also wrapped in `MsalProvider` for msal-react hooks.
- **Routing mirrors the API access gate.** `RequireState` sends each account state to its page
  (`/onboarding`, `/under-review`, `/rejected`, `/app`, `/owner`). The API remains the authority
  (403 for non-active users); the client guard is only for navigation.
- **Typed API.** `openapi-fetch` + types generated by `openapi-typescript` from
  `apps/web/openapi.json` (exported by `python -m kloudrecon.cli export-openapi`). Both files are
  committed, so CI's frontend job does not need the backend.
- **Navigation.** Modules from later phases (Inventory, Security, FinOps …) appear in the sidebar
  with a "Soon" badge and are not clickable, rather than linking to empty pages. This keeps the
  information architecture of plan 14.4 visible while being honest about availability.
- **Pricing page** reads `/api/v1/public/plans` and falls back to the plan Section 18 defaults when
  the API is unreachable.
- **TypeScript 5.9** (not 6/7): `typescript-eslint` and `openapi-typescript` peer ranges.
